## Implemented

- Added `src/modules/ai-platform-core/mcp-streamable-http-resolver.ts` as the first host-owned Streamable HTTP implementation behind the existing resolver interface.
- The resolver only uses approved HTTPS DNS hostnames, validates every DNS answer as public, pins each outbound request to a checked IP, verifies TLS, refuses redirects, applies request/response size bounds and timeouts, and propagates the server request's cancellation signal.
- Added JSON-RPC initialize / initialized notification / paginated tools-list / tools-call handling with a bounded supported JSON Schema subset, Zod input validation, duplicate-tool rejection and stale-schema rejection.
- The resolver rechecks platform enablement, allowed plan, organisation connection, platform tool approval, organisation grant, agent grant, caller membership, KB read access, tenant/agent/KB binding, session context and chat/realtime surface at discovery and invocation. Credentials are decrypted in-process from the existing encrypted connection store and are not logged or returned.
- Added `inputSchemaJson` to the host resolver descriptor for bounded provider tool advertisement; schema output is normalized and deeply frozen.
- Added migration `070_mcp_connection_handshake_status.sql` so a successful discovery can be recorded as `connected` while preserving the encrypted-credential constraint. Resolver writes handshake time only after valid discovery; the organisation UI shows the last handshake and supports bearer credential rotation.
- Extended `buildMcpToolRuntime` with optional request-scoped runtime composition. Chat builds a fresh Clara runtime and adds authorized MCP capabilities to the existing tool-calling loop; MCP capabilities are not registered on the process-global runtime.
- OpenAI realtime session setup advertises discovered MCP tools only for an authenticated, non-platform-admin tenant member with KB read access. The realtime tool endpoint maps the provider tool alias back to an exact currently granted server/tool pair and dispatches through a dedicated Unified Tool Runtime.
- Exported the resolver and request-scoped Clara runtime factory from `src/modules/ai-platform-core/index.ts`.
- Added `src/modules/ai-platform-core/mcp-streamable-http-resolver.test.ts` for public/private IP and unsafe endpoint validation.

## Security and operating decisions

- Keep platform MCP servers disabled by default and retain `ENABLE_MCP=false` as the default kill switch. No production server should be enabled based on source review alone.
- Unsupported transport, unsupported schemas, unapproved tools, missing caller/tenant context, plan or grant failures, private DNS answers, redirects, TLS failures, stale schemas, timeouts and oversized responses fail closed.
- No shared discovery cache was introduced. Each resolution/invocation rechecks grants and the remote tool list, avoiding stale cross-tenant capabilities while cache invalidation semantics are still undefined. This currently costs additional upstream round trips and is a follow-up performance task.
- Resolver errors are normalized before being surfaced to the model; operational logs include only a bounded failure code and server/tool identifiers, never credentials or raw response bodies.
- The server-side MCP transport is currently implemented for OpenAI realtime session advertisement plus the existing shared realtime dispatch route. Other voice providers are not claimed as MCP-enabled unless their tool advertisement and dispatch path is separately verified.
